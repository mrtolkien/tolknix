# AGENTS.md

Guidance for coding agents working in this repository. See `README.md` for
installation and day-to-day usage.

## Essential tool

You have access to the Nix MCP which lets you:

- Query nix packages
- Query home-manager and nix-darwin options
- Search Nix docs

Use it extensively to validate your assumptions.

## Commands

Run from the repository root.

```bash
# Format, then lint and build this machine's config without applying it
nix fmt
nix flake check

# Apply
home-manager switch --flake .#tolki@cachyos   # Linux
sudo -H darwin-rebuild switch --flake .#mbp   # macOS
```

`nix flake check` runs `nixfmt --check`, `statix` and `deadnix`, and builds the
configuration of the current platform. It must pass before committing. New
files must be `git add`ed first, or the flake does not see them.

## Layout

| Path                       | Purpose                                             |
| -------------------------- | --------------------------------------------------- |
| `flake.nix`                | Both targets, formatter, checks                     |
| `common/home.nix`          | Shared home-manager programs and dotfile links      |
| `common/packages.nix`      | Install-only packages for both platforms            |
| `darwin/configuration.nix` | nix-darwin system settings                          |
| `darwin/home.nix`          | macOS home-manager entry                            |
| `darwin/packages.nix`      | macOS-only packages                                 |
| `linux/home.nix`           | Linux home-manager entry: identity, locale, Nix GC  |
| `linux/desktop.nix`        | Hyprland, Noctalia, Vicinae, IME, MIME associations |
| `linux/packages.nix`       | Linux-only packages                                 |
| `*/dotfiles/`              | Config files, mirroring the layout of `~/.config`   |
| `darwin/scripts/`          | AeroSpace scripts, linked into `~/scripts`          |

## Conventions

- Tools that need configuration or shell integration go through `programs.*`
  in a `home.nix`; install-only tools go in a `packages.nix`.
- Each `packages.nix` is a module setting `home.packages`. A package in
  `common/packages.nix` must exist on both platforms; a Linux-only package
  there breaks evaluation of the macOS target.
- Dotfiles live at `<platform>/dotfiles/<path under ~/.config>` and are linked
  with `xdg.configFile`.
- Platform files import `common/home.nix` and extend it; use `lib.mkAfter` to
  append to shared shell init.
- Home Manager state version is 24.11 and nixpkgs follows `nixos-unstable`.

## Linux desktop

- Hyprland itself is installed by pacman. Its Lua configuration lives in
  `linux/dotfiles/hypr/` and is linked file by file into `~/.config/hypr/`,
  which stays a writable directory.
- Hyprland resolves the Home Manager symlinks, so `hyprland.lua` prepends
  `~/.config/hypr` to `package.path`; keep that at the top of the file.
- `~/.config/hypr/noctalia.lua` is generated by Noctalia and must stay mutable;
  do not add it to this repository or put manual settings in it.
- `hyprland.lua` loads `~/.hypr/temp.lua` last when it exists. It is an
  unmanaged scratch file for quick tests; move what sticks into
  `linux/dotfiles/hypr/`.
- `hypr/scripts/focus-or-launch` is called from the Vicinae Leader Key
  configuration, not from this repository; it is not unused.
- Noctalia's settings live in `linux/dotfiles/noctalia/config.toml`. The
  settings UI still works: it saves overrides to
  `~/.local/state/noctalia/settings.toml`, which wins over the Nix-managed
  file. The comment in `linux/desktop.nix` explains how to fold UI changes
  back in.
- Vicinae keeps its own mutable config; Home Manager only installs it and owns
  its service.
- System packages that are not suitable for Nix remain managed by pacman/yay.

Validate Hyprland changes after a switch:

```bash
hyprctl reload && hyprctl configerrors
```

## macOS

- The macOS target cannot be built on Linux, but it can be evaluated there:
  `nix eval .#darwinConfigurations.mbp.system.drvPath`.
- Without `xdg.enable`, lazygit reads its config from
  `~/Library/Application Support/`; `common/home.nix` picks the path per
  platform.
- Ghostty loads `darwin.conf` through an optional include at the end of the
  shared config.
